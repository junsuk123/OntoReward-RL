## 20. ORL — 온톨로지를 정책의 inductive bias로 (2026-11-02)
- **목표:** 착륙의 검증 지점 전부를 정책의 inductive bias로 만든다. CNN의 합성곱, LSTM의 게이트처럼, R-GAT로 표현된 온톨로지 *때문에만* 강화학습 정책에 inductive bias가 생기게 한다.
- **진단:** 그래프 판독을 원 관측 옆에 붙이는 구조는 MLP가 그래프를 무시할 수 있으므로 함수 공간이 제한되지 않는다. 즉 귀납 편향이 없다. CNN의 편향은 덧붙인 정보가 아니라 *제약*에서 나온다.
- **ORL** (`current_semantics/orl.py`, arm `orl_ppo:eb68eb947a6a49a2`, `ORL_HASH`). 네 가지 bias는 모두 온톨로지 선언에서 나온다.
  1. **국소성(receptive field):** raw 우회가 없다. 행동은 phi44를 개념 노드를 통해서만 읽는다. 노드 유형마다 자기 slot만 encode하고, 정보는 선언된 관계로만 흐른다.
     - LateralDecision_x는 y 평면 개념을 어떤 홉 수로도 읽지 못한다. 검사로 확인한다.
  2. **가중치 공유(convolution kernel):** 3D 과제를 기준 2D landing 평면이 수평축마다 하나씩 있는 것으로 본다(`landing/plane_graph.py`의 원리).
     - x와 y 평면은 같은 개념의 두 인스턴스다. node encoder, 관계 가중치, lateral readout을 공유한다.
     - 공유가 같은 물리를 뜻하도록 y 평면의 부호를 맞췄다.
       - 카메라 y = −body y이므로 영상 좌표는 −η를 쓴다.
       - a_x는 +sin(pitch), a_y는 −sin(roll)을 따른다(scipy "xyz" ENU/FLU 추력 방향). 각속도도 같은 규칙이다.
     - FOV 비대칭(90° 대 73.7°)은 다른 가중치가 아니라 정규화된 영상 좌표와 margin 값으로 들어간다.
  3. **등변성(translation equivariance에 해당):** 개념마다 두 거울 반사에 대한 parity를 선언한다(`PLANE_ROLES`, `MARGINS`, `SHARED_ROLES`).
     - 평면 개념은 그 평면의 거울에서 부호가 바뀐다. 평면의 view margin 쌍은 서로 바뀐다. heading은 두 거울 모두에서 바뀐다. 나머지는 불변이다.
     - actor 평균은 네 반사에 대한 군 평균이다. 그래서 거울에 비친 상태에는 정확히 거울에 비친 명령이 나온다.
     - **측정:** 선언된 parity와 `build_features`에 반사된 세계를 넣었을 때의 결과는 view 항목을 빼고 완전히 같다(오차 0). view 항목은 등록된 주점(cx 320 대 픽셀 중심 319.5) 때문에 |Δ| ≤ 4.2e-3이다.
  4. **학습되는 gate(LSTM gate에 해당):** 이 연구의 검증 지점들이 DescentEligibility에서 만난다.
     - ContactCondition: 접지 판정의 속도·기울기·각속도 한계와 패드 반경.
     - ViewGeometry: 카메라 footprint margin.
     - ObservationQuality: vision age.
     - DescentEligibility는 Q, C_x, C_y, O_x, O_y만 읽는다.
     - 수직 평균은 `hold(Z) + sigmoid(gate(E)) · descend(Z)`다. gate는 학습되고 고정 규칙이 아니다(반쯤 열린 상태로 시작). 행동은 여전히 `a_max·tanh(z)` 하나다.
- **그래프:** 노드 19개(공유 Q·V·H, 평면마다 G·M·A·P·O·C·L, 그리고 E·Z), 관계 8종(기존 5종 + gatesDescent, informsVertical, self), 간선 61개. 관계 층 하나를 공유하고 3홉을 돈다. embedding은 14다.
- **예산:** actor 2,747, 합계 4,016이다(비교 정책 4,008–4,022). critic(raw21)과 log_std는 공통이다.
  - 군 평균이 상쇄하는 lateral 출력 bias는 두지 않았다. 죽은 parameter 0개를 검사로 확인한다.
- **경계:**
  - ORL은 v1 계약의 등록 arm이 아니다. v1의 모든 hash와 등록은 그대로다(스냅샷 비교: IDENTICAL).
  - checkpoint는 arm 이름의 ORL_HASH로 묶이며, 등록 arm과 서로 load되지 않는다.
  - 시뮬레이터 truth는 정책에 들어가지 않는다. 한계값은 과제 상수다.
  - guard: `tests/current_semantics/test_cs3d_orl.py`, 15개 테스트. 정확한 등변성, 물리 거울, 평면 정렬, 평면 교환, lateral 국소성, gate, 예산·죽은 parameter, aliasing을 본다.
- **선택의 근거와 한계:**
  - 등변성과 평면 공유는 물리에서 오는 정확한, 혹은 근사적인 대칭이다. 그래서 정답 함수를 배제하지 않는다.
  - descent gate와 lateral 국소성은 *가설*이다. 축 간 결합(추력 공유, 2D 패드 운동)이 중요하다면 비용이 될 수 있다.
  - 편향을 한 번에 넣었으므로 개별 기여는 분리되지 않는다. 필요하면 하나씩 뺀 ablation으로 잰다.
  - `orl/1`의 학습된 하강 게이트는 학습 후 모델마다 거의 상수였다(표준편차 ≤ 0.027). 그래서 21·24절의 결과는 실제로는 국소성, 평면 가중치 공유, 거울 등변성 세 편향의 효과로 읽는다.

## 21. 학습 속도 확인 `learning-speed/1`: ORL 대 PPO·Untyped GNN (2026-11-20)

### 21.1 왜 이 실험인가

- Kinematic WLS 추정기(내부 명칭 WMON)는 저자의 별도 연구 결과이므로, 그 조건에 기대는 결과는 착륙 정책 연구의 기여를 흐린다. 그래서 기준 항법만 쓴다.
- 제안 모델은 ORL이다. 학습 속도의 차이를 새 시드와 학습 전에 등록한 규칙으로 확인한다.

### 21.2 등록 (`learning_speed/learning_speed_registration.json`, 2026-11-20, plan hash `801902de…`)

- 코드와 설정: `current_semantics/speed.py`, `config/current_semantics/learning_speed_v1.yaml`. 테스트는 `tests/current_semantics/test_cs3d_speed.py`.
- 조건: 기준 항법 계약(`spatial_view_contact_v1.yaml`)만 쓴다. 항법 추정기가 들어간 설정은 WLS와 CA-KF 모두 거부한다.
- 모델: ORL(`orl/1` = `orl_ppo:eb68eb947a6a49a2`, 손으로 만든 규칙 없음), Untyped GNN, PPO(raw).
- 시드:
  - 학습 시드 40–49. 0–1, 10–14, 20–39는 다른 프로토콜이 썼거나 예약해 두었다.
  - 에피소드 시드는 340,000,000–349,007,199이고, 이미 쓰인 모든 범위와 겹치면 `_audit`가 거부한다.
- 학습: 기준 계약의 G4 레시피를 그대로 쓴다(업데이트당 12 에피소드, 커리큘럼, PPO 설정, 학습 무작위화).
  - 난이도 1.0으로 학습한 첫 업데이트에서 멈추고, 상한은 600이다.
  - 체크포인트 선택과 평가는 하지 않는다.
- 판정 규칙(`speed.RULE`, 해시에 포함):
  - 시드마다 d = ln T(ORL) − ln T(X)를 계산한다. 상한까지 도달하지 못하면 T = 600으로 둔다.
  - 두 비교 각각 양측 paired-t 97.5 % 구간을 쓴다(Bonferroni).
  - 구간 상한이 0보다 작고 ORL 모델 중 중도절단이 없으면 "faster", 하한이 0보다 크면 "slower", 그 밖은 "not established"다.
  - 부호검정과 평균 비는 보고만 하고 판정에 쓰지 않는다.
- 실행: 2026-11-20 12:30 KST에 `--stage speed` 프로세스 4개를 띄웠다(각 3 worker, 모델은 claim으로 나눈다).

## 24. 같은 예산 착륙 성능 `equal-budget/1`과 Isaac 평가 `isaac-equal-budget/1` (2026-11-20)

### 24.1 왜 이 실험인가

- `learning-speed/1`(§21.3)은 커리큘럼을 끝까지 올라가는 속도만 쟀다. 모델은 그 업데이트에서 멈췄고 평가하지 않았다.
- 남은 질문은 두 가지다.
  - 같은 학습 예산에서 ORL이 더 잘 착륙하는가?
  - ORL 정책이 Isaac Sim + PX4에서도 착륙하는가?

### 24.2 `equal-budget/1` 등록 내용 (`config/current_semantics/equal_budget_v1.yaml`, `current_semantics/budget.py`)

- 정책: ORL(`orl/1` = `orl_ppo:eb68eb947a6a49a2`), Untyped GNN, PPO(raw). `learning-speed/1`과 같다.
- 학습 시드: 50–59. 0–1, 10–14, 20–39, 40–49는 다른 프로토콜이 썼다(로더가 겹침을 거부한다).
- 학습 에피소드 시드: 450,000,000–459,007,199. 감사한 모든 범위와 겹치지 않는다.
- 학습: 기준 계약의 G4 레시피를 600 업데이트 동안 그대로 쓴다.
  - 업데이트 100, 200, 600 직후의 가중치를 그대로 저장한다(`pilot.train_seed(snapshots=...)`).
  - 검증과 체크포인트 선택은 하지 않는다(`validate=False`).
- 예산은 학습 전에 `learning-speed/1`(다른 시드)에서 정했다.
  - 100: 비교 정책이 최고 난이도에 처음 도달한 중앙값(100, 107)
  - 200: `learning-speed/1`에서 도달한 모든 모델이 이미 도달한 뒤(가장 늦은 도달 140)
  - 600: 기본 학습 예산
- 평가: 평가 셀 10개(`development.cell_conditions`, 결정론적 정책, 난이도 1.0)를 쓴다.
  - 셀마다 50 에피소드이다.
  - 환경 시드는 70,000,000부터 새로 쓴다. 같은 학습 시드의 모든 정책과 예산이 같은 환경을 비행한다.
- 판정 규칙(`budget.RULE`, 해시에 포함):
  - 모델 점수는 예산 B에서 셀 10개 성공률의 평균이다.
  - 비교 정책 X마다 학습 시드별 차이 점수(ORL) − 점수(X)의 양측 paired-t 97.5 % 구간(Bonferroni, 비교 2개)을 구한다.
  - 하한 > 0이면 better, 상한 < 0이면 worse, 그 밖은 not established이다.
  - 예산은 100 → 200 → 600 순서의 고정 순서 검정이다. better나 worse가 나와야 다음 예산을 검정한다. 멈춘 뒤의 예산은 판정 없이 보고만 한다.
- 규모: 모델 30개, 학습 에피소드 216,000개, 평가 에피소드 45,000개.
